# R2.8.84 app.json source boundary

## Repository evidence

- `fixtures/configuration-inventory.json` contains a root `.obsidian/app.json`
  with top-level `showLineNumber: true`, CRLF bytes, and an unknown nested key.
- Existing Rust discovery retains valid JSON objects, their exact source bytes,
  and unknown fields. It currently has typed projections for appearance and
  root hotkeys files; it has no app settings type or consumer for this field.
- The legacy configuration loader treats other object JSON as generic source
  data. This slice preserves that behavior and only reads the one existing
  fixture-backed Boolean field.

## Bounded projection

Project `showLineNumber` from root `.obsidian/app.json` and alternate
configuration roots into `AppSettings`. Keep the value optional: a missing or
non-Boolean field maps to `None`, while `false` remains `Some(false)`. Keep the
parsed object and original bytes authoritative. Nested plugin `app.json` files
remain in the generic JSON inventory and do not become vault app settings.

This is a fixture-backed source-data projection. It does not establish a full
`app.json` schema, change the native UI, choose a default, or write preferences.
The public documentation search did not identify a serialization contract for
this field; no broader compatibility claim is made.

## Independent candidate review

Two read-only reviews compared remaining configuration files. The smaller
`app.json` projection was selected ahead of community-plugin ID arrays because
the latter require a separate raw-array path outside generic object discovery
and can be confused with the remote plugin registry catalog. Workspace state
also remains opaque because its fixture is a non-object array and its real
nested shape is substantially broader.

## CI-only acceptance

The implementation milestone requires the seven source workflows on its exact
pushed SHA, including Rust CI on Ubuntu, macOS, Windows and Rust 1.95 and the
path-filtered Obsidian round-trip. Tests, formatting, builds, and validation
must run only in GitHub Actions. The following tracker commit records the
R2.8.83 acceptance checkpoint: `evidence/r2.8.83-tracker-checkpoint-9176467.json`.
