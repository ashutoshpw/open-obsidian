## Current evidence

The pinned Obsidian 1.14.4 round-trip currently covers source-preview open/close,
external Markdown note creation followed by refresh and preview, and native
resolution/rendering of an Obsidian-authored image embed. The latest accepted
reference-app slice is C01.2-41 on source SHA
`e78409a4c721e63c866ee6b7fd4411d96c277ded`; its exact-SHA Linux, macOS, and
Windows artifacts and seven required workflow results are recorded in
`evidence/r2.8.73-c01.2-41-e78409a.json`.

Attachment removal is covered by synthetic egui tests, including
`egui_refresh_after_external_attachment_removal_clears_stale_embed_without_writing`
in `crates/ui-egui/src/lib.rs`. That coverage proves Rust UI state transitions
but does not exercise the pinned Obsidian-authored vault through the running
desktop application.

The GitHub Actions native `parallel:` step feature discussed in the June 25,
2026 changelog is already implemented in six workflows, including Rust CI,
quality, desktop packaging, and the vault round-trip. Its setup was accepted in
prior exact-SHA CI runs and is recorded under `ci_preparation` in `state.json`.
Remaining workflows have dependency-ordered setup and a single validation step,
so no additional safe independent group was identified during this audit.

## Selected bounded gap

R2.8.74 adds C01.2-42 to the reference-app matrix. While OpenObsidian is still
open with the authored image displayed, the harness removes only
`Assets/roundtrip image.png` externally. It then records the watcher state,
requests an explicit UI refresh, rejects stale resolved/image output, and runs a
fresh resolution that must be unresolved, targetless, and `not_rendered`. The
harness compares full vault snapshots against the deliberate post-removal
baseline and enforces the existing separate app-data policy. It later reopens
the vault in Obsidian, proving the embed source remains in the authored note
while the deleted image remains absent.

This is a deliberately external fixture mutation inside the isolated CI vault.
OpenObsidian and Obsidian must not write back to the fixture. The full slice
must pass through GitHub Actions on Linux, macOS, and Windows; no local tests,
builds, formatters, linters, application launches, or other executable
validation are permitted by the migration goal.
