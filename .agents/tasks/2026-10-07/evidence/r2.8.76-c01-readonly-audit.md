# R2.8.76 read-only reference-app audit

## Current checkpoint

The latest accepted Rust implementation is 938f4cda4885efc09d75e6d1eeb182398cacf229. C01.2-43 adds cross-platform Obsidian 1.14.4 evidence for an external in-place note edit while OpenObsidian previews the note, followed by refresh, a fresh source preview, no-op close, and reference-app reopen.

Parent C01 and C01.2 remain pending. Their acceptance requires broader read-only coverage and byte/hash snapshots, not just successful startup or a single preview.

## Remaining reference-app gap

C01.2-24 already exercises an external note rename, refresh, stale preview clearing, fallback selection, and re-preview in the synthetic egui harness on Ubuntu, macOS, and Windows. The pinned Obsidian reference-app round trip does not yet exercise this flow.

The reference-app sequence currently proves source preview, external note creation and edit, image-embed resolution, external attachment removal, picker cancellation, and Obsidian reopen. The missing cross-app operation is renaming a note with its source preview open, preserving every source byte while the path changes, refreshing the selected vault, and reopening the renamed note in Obsidian.

## Selected case: C01.2-44

Begin from the Obsidian-authored vault after C01.2-43 has externally created and edited After refresh.md. In the running OpenObsidian desktop, select the note and visibly preview its updated BOM/CRLF source. Rename it externally to After refresh renamed.md while the preview is open.

The external mutation must change exactly two snapshot entries: remove the old path and add the new path with identical byte length and SHA-256. The Markdown count and separate OpenObsidian app-data snapshot must remain unchanged. After the native refresh, require the stale preview marker to disappear, the application diagnostic to report the exact fallback selection, and the visible Markdown count to remain correct. Re-preview the renamed source and close it; compare the full vault and app-data snapshots against the post-rename baseline.

Close OpenObsidian, reopen the same vault in Obsidian 1.14.4 in Restricted Mode, and verify the old path is absent, the renamed path is visible and selected, and its exact bytes and updated source marker remain. Compare the final tree against the post-rename snapshot, allowing only the already validated Obsidian workspace-state paths. Collect Linux, macOS, and Windows artifacts and require all seven project workflows on the exact implementation SHA. All executable validation remains in GitHub Actions.

This case covers one externally renamed note in an Obsidian-authored vault. It does not close the broader C01/C01.2 requirements or certify native in-app editing and saving.
