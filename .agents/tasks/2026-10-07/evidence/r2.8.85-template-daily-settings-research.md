# R2.8.85 template and daily-note settings source boundary

## Repository evidence

- The legacy parser in `src/shared/ui/note-workflows.ts` projects the
  `folder` field from `templates.json` and the `folder`, `format`, and
  `template` fields from `daily-notes.json`.
- `src/core/note-workflows.ts` reads `.obsidian/templates.json` and
  `.obsidian/daily-notes.json`; `tests/note-workflows.test.ts` records the
  current defaults, a normal daily-note plan, and unsafe folder/template
  examples.
- C09 requires explicit mapping of supported preferences while retaining
  unknown JSON fields and exact bytes. Rust already keeps generic configuration
  objects and raw bytes alongside typed maps keyed by vault-relative paths.
- The configuration inventory fixture currently has no template or daily-note
  settings files or parser cases. The existing inline TypeScript tests are
  useful behavior evidence but do not replace Rust fixture coverage.

## Legacy projection semantics

- Template `folder` defaults to the empty string. An empty string is allowed;
  other values must pass the relative-path checks. Invalid values project as
  the empty string and add an issue.
- Daily-note `folder` follows the same rules. `format` defaults to
  `YYYY-MM-DD` when absent, non-string, or blank; a nonblank string is trimmed
  using JavaScript whitespace rules. `template` becomes absent for missing,
  `null`, or an empty string; otherwise it must pass the relative-path checks.
- The path checks reject leading `/`, backslashes, NUL, empty segments, `.`
  segments, and `..` segments. They are parser behavior only and do not
  authorize filesystem access or establish a complete cross-platform path
  policy.
- The Rust projection functions consume parsed JSON object maps. The legacy
  parsers also report a separate issue for top-level non-object inputs, but C09
  discovery omits malformed and non-object JSON files before typed projection;
  that input-level issue is outside this object's projection contract.
- Unknown fields and the exact source bytes remain authoritative. These
  projections must not rewrite configuration or drive UI behavior.

Rust may project these root filenames from every recognized `.obsidian` and
`.obsidian-*` configuration folder, consistent with its existing C09 root
discovery. The legacy note workflow reads only `.obsidian`; alternate-root
projection should be described as Rust C09 discovery behavior, not exact
legacy workflow parity.

## Bounded implementation

Add inert `TemplateSettings` and `DailyNoteSettings` data projections in
`crates/doc`, then add exact-root-file maps in `crates/vault`. Retain each file
in the generic JSON inventory with its original bytes. Extend
`configuration-inventory.json` with valid, default, invalid-type, and unsafe
path cases; include unknown keys, CRLF preservation, alternate-root coverage,
and nested plugin decoys. Assert the projection does not mutate the source
object and does not change the vault snapshot.

Keep template indexing, date-token expansion, daily-note planning, template
execution, note creation, and writes out of this slice. Those are separate
workflow behavior and do not establish C10 acceptance. Treat the selected
fields as behavior observed in this repository, not a complete Obsidian
settings schema.

## CI-only acceptance

All Rust tests, formatting, builds, and validation for this slice must run only
in GitHub Actions. Push a small source-phase commit to `origin/main` and accept
it only after the exact-SHA required workflows pass. C09 and C09.1 remain
pending.
