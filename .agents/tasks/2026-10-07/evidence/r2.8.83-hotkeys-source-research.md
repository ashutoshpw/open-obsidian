# R2.8.83 hotkeys source-shape research

## Findings

The existing TypeScript configuration loader recursively discovers JSON files
under each root `.obsidian` / `.obsidian-*` folder, keeps the parsed object and
original file bytes, and adds a typed projection only for `appearance.json`.
The Rust inventory follows the same lossless JSON pattern and currently has no
vault hotkeys model or fixture. OpenObsidian's own shortcut catalog is separate
in `src/shared/ui/keyboard.ts` and is not a vault command registry.

Obsidian's public API defines a `Hotkey` as `modifiers: Modifier[]` plus a
string `key`. Its modifier documentation gives platform-specific meanings to
`Mod` and `Meta`; command documentation says user customizations take priority
over default bindings. The Help page describes hotkeys as Obsidian command
shortcuts, distinguishes them from operating-system editing shortcuts, and
allows several combinations per command. Those pages do not fully specify the
serialized `hotkeys.json` format, so the fixture pins only the narrow object
shape that this data-only projection supports.

## Bounded projection

- Project only `<configuration-folder>/hotkeys.json` at each root; keep nested
  plugin JSON available in the generic inventory without treating it as
  vault-global hotkeys.
- Key each projection by its normalized vault-relative path so desktop/mobile
  configuration roots remain distinct.
- Project command IDs whose values are arrays into ordered binding lists.
  Preserve empty lists, modifier order/spelling, unknown modifier names, and
  key strings exactly. Do not infer a platform's effective key combination.
- Omit malformed command values and malformed binding entries from the typed
  projection while keeping them intact in the original parsed JSON and bytes.
- Do not merge core/plugin defaults, resolve command IDs against installed
  plugins, normalize key strings, detect conflicts, register shortcuts, or
  route vault bindings through OpenObsidian's app-owned shortcut dispatcher.

## Fixture and CI plan

Extend `fixtures/configuration-inventory.json` with desktop and mobile root
hotkeys files, a nested plugin hotkeys file, opaque command IDs, ordered
alternate bindings, an empty list, platform modifier aliases, an unknown
modifier, unknown fields, and malformed entries. The existing vault inventory
assertions continue to compare exact source bytes and parsed JSON and compare
vault snapshots before and after discovery. Unit and integration tests cover
lossless source, root scoping, root isolation, ordering, and no dispatch.

Only GitHub Actions may run tests and other executable validation. Push the
source milestone and accept it only when inventory, quality, desktop build,
plugin renderer, loaded plugin, Rust CI (Ubuntu/macOS/Windows and Rust 1.95),
and Obsidian round-trip workflows pass on the exact implementation SHA.
