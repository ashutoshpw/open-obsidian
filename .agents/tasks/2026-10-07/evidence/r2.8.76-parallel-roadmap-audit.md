# Parallel Rust migration gap audit after R2.8.76

This is a read-only roadmap audit from three parallel agents, reconciled against
the R2 phase sequence in `goal.md`. It identifies candidate work; it does not
change any requirement's acceptance status. Executable validation remains
GitHub Actions only.

## Recommended next slice: C08.1 external open

`C08.1` requires unknown binary files to retain their original hashes and be
available through an external-open action that uses the original file path.
Rust vault snapshots already preserve opaque regular files, but no Rust
platform opener or accessible product action was found. The Electron behavior
uses `shell.openPath`.

Bound the first Rust slice around a vault-confined resolver for a regular file,
a platform opener interface, and a native UI action. Inject the opener in the
CI test to assert the exact absolute path without launching another application.
Cover an unknown binary's original path and hash, and reject missing paths,
directories, traversal, and symlink targets. Keep the resolver in the vault
boundary and the OS-specific launch adapter behind the platform boundary.

## Other R2 candidates

- **C09 configuration inventory:** Rust currently preserves `.obsidian` as
  opaque files; it does not discover/map Obsidian configuration. A small
  substrate is read-only inventory of `.obsidian` and `.obsidian-*` JSON/CSS
  bytes and hashes without following symlink directories. Semantic appearance
  and theme projection should follow separately. C09.1's legacy explicit
  `configuration.write` denial belongs at the plugin capability-policy
  boundary (`crates/plugins`), although the current requirement row says
  `crates/platform`; ownership needs reconciliation before that slice.
- **C06 Canvas and C07 Bases:** no Rust implementation/evidence was found.
  Read-only source-preserving Canvas and bounded `.base` parsing are larger
  follow-on document/workspace slices; legacy TypeScript evidence alone does
  not count as Rust acceptance.
- **D16/SYNC-006 and GATE-003:** substantial failure, retention, and
  recovery-related Rust evidence already exists. The remaining concerns are
  specific external persistence/host gaps, not a good first follow-on slice.

## R1 tracker discrepancy to reconcile

`state.json` marks R1 complete while six requirement rows remain tagged to R1
and pending: `Q-006`, `Q-009`, `MIG-003`, `MIG-004`, `MIG-006`, and `MIG-015`.
The audit found three-OS compatibility/runtime evidence for `MIG-003`; `MIG-004`
declares Rust 1.95 but historical CI used newer stable Rust 1.99; `MIG-006`
has no explicit cancellable-work evidence; and `MIG-015` still lacks a clear
required D15 unsupported-path disposition. `Q-006` responsiveness and `Q-009`
AI grounding appear to belong to later native editor and AI phases. Keep these
rows pending until their phase assignment and acceptance are reconciled; do
not promote legacy-only or partial evidence.

## Recommendation

After the R2.8.76 documentation checkpoint passes its path-eligible CI, start
R2.8.77 on C08.1. Preserve the exact-path assertion and all symlink/traversal
denials across Linux, macOS, and Windows, and run executable validation only
through the required exact-SHA GitHub Actions workflows. Reconcile the R1 row
assignments in a separate tracker slice before using the R1 completion status
as final migration evidence.
