## Three editor workflows

The legacy contract defines `EditorMode = "source" | "live-preview" | "reading"` in `src/shared/api.ts`. `renderEditorMode` in `src/renderer/renderer.ts` shows only the editor in source mode, both editor and rendered preview in live-preview mode, and only the rendered preview in reading mode. The mode buttons select these values and the workspace settings retain the selected default.

| Mode | Legacy behavior | Rust behavior on the audited tree | Direct Rust coverage |
| --- | --- | --- | --- |
| Source | Source editor visible; rendered preview hidden. | The note panel can display original source and has an explicit `Edit Markdown source` action. There is no source-mode state or mode selector; source editing replaces the panel's rendered preview branch. | `egui_source_edit_saves_exact_bom_crlf_and_unsupported_markdown_bytes`, `egui_source_edit_saves_a_table_cell_without_normalizing_markdown`, and stale-edit coverage exercise the explicit draft/save path, not a selected Source mode. |
| Live preview | Source editor and rendered preview are visible together. | The panel renders supported Markdown and shows original source below it. When a source draft is active, the current UI renders the source-editor branch instead of the preview, so it does not provide the legacy simultaneous source-edit/preview workflow. | `R2.8.67` maps 22 preview cases and source-edit tests, but no test selects or checks a Live preview mode. |
| Reading | Rendered preview visible; source editor hidden. | The same preview panel can render Markdown, but it has no distinct Reading mode and still exposes source-oriented controls and original source. | Preview fixture tests prove rendering/fallback behavior, not a read-only Reading workflow. |

**Mode conclusion:** Parent C02 is not satisfied. Rust has preview and revision-checked source-edit capabilities, but it does not yet offer the three separate workflows or preserve the draft while switching between them. The gap is in UI state/presentation and mode-specific interaction coverage, not in the legacy requirement interpretation.

## Decision and next slice

Keep `C02` pending. The next implementation slice should add explicit Source, Live preview, and Reading controls to the native note workflow. Source mode must edit a revision-bound draft; Live preview must present the source editor and its rendered result together; Reading must show the rendered result without source-edit controls. Switching modes must retain an unsaved draft, and only explicit save may write through the existing revision-checked vault writer. Add mode-specific UI tests and a representative exact-byte fixture that carries BOM, CRLF, significant whitespace, YAML and Markdown comments, unknown syntax, and untouched spans through preview, mode switches, and an approved source edit. Validate it in GitHub Actions on the supported desktop matrix; run no local executable validation.
