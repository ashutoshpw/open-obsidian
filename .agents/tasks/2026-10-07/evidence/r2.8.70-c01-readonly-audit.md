# R2.8.70 — C01/C01.2 read-only vault audit

Audit baseline: repository head `8cf701b825ba13b9715388a6c3fbc313547bfdf6`.
The source SHA for each executable claim is recorded separately below or in
the linked GitHub Actions evidence. This audit changes no product code and does
not replace exact-SHA CI evidence.

## Conclusion

The Rust vault layer and egui UI have broad cross-platform snapshot coverage
for read-only operations. The tests prove that the tested operations preserve
vault paths and bytes, and where the UI harness has a separate app-data tree,
that it remains unchanged as well. The native reference-app evidence is
narrower: pinned Obsidian 1.14.4 authored a synthetic vault, OpenObsidian opened
it, and Obsidian reopened it with the expected note and attachment. A separate
native picker case covers selection/reopen, and a later case covers picker
cancellation. Most refresh, preview, link, embed, recovery, and symlink cases
are synthetic Rust UI or vault fixtures; they do not establish those same
flows in the actual OpenObsidian desktop against the Obsidian-authored fixture.

Therefore C01 and C01.2 remain pending. The recorded tests support the Rust
implementation, but do not yet cover every read-only product operation on an
Obsidian-authored vault through the reference-app matrix on all three OSes.

## Remaining gap and next bounded slice

The smallest next reference-app slice is to extend the existing native
round-trip workflow with one actual OpenObsidian read-only operation against
the Obsidian-authored note: open the vault, request its source preview, close
the preview/session without edits, and compare full vault plus app-data
snapshots before and after on Ubuntu, macOS, and Windows. Preserve the current
Obsidian reopen assertion and upload screenshots/report data. Track it as
C01.2-39 / R2.8.71. Keep C01/C01.2 pending until that and the other missing
reference-app flows have direct evidence.
