# Rust migration decisions

Recorded for R0.2 on 2026-10-07. These decisions clarify implementation and evidence policy under the approved Rust migration goal; they do not certify implementation.

| ID | Decision | Evidence and consequence |
| --- | --- | --- |
| RM-01 | Use the Photocraft native stack as declared in its pinned workspace: Rust 2024 / minimum 1.95, Cargo resolver 3, eframe/egui 0.36 with wgpu, Serde, thiserror, log, Rayon, and workspace `unsafe_code = "forbid"`. Keep a project Cargo.lock and use locked CI builds. | Source manifests and CI at PhotoCraft commit `47f9306fd06d5dee11acb84b108606f4c867222a`, cited in `goal.md`. Photocraft-only codecs and image algorithms are excluded. OpenObsidian-specific dependencies require license, purpose and version records. |
| RM-02 | Keep authoritative vault files lossless and SHA-256 revision contracts unchanged. Keep preferences, derived indices, embeddings and recovery state in app-owned storage. | Existing vault and storage contracts plus the migration goal. BLAKE3 in Photocraft is not a replacement for the existing SHA-256 contract. |
| RM-03 | Preserve the selected top-25 plugin IDs, dependency scope and recorded compatibility artifacts as migration acceptance targets. A ranking-refresh failure is discovery drift; it does not silently replace the approved cohort. | Existing selection evidence, `fixtures/plugin-catalog.json`, compatibility manifests and GitHub run 37261648547. Record updated popularity separately and retain the public 1.13.7 stable baseline. |
| RM-04 | Make unchanged JavaScript/DOM plugin compatibility an early feasibility gate before broad native UI investment. The WASM/wasmi host may serve Rust-era extensions, but it does not execute existing JavaScript bundles or establish their certification. | Existing PC01–PC25 workflows and Photocraft `crates/plugins/Cargo.toml`. R1 must exercise representative editor, query/script, DOM theme and denied-capability cases in GitHub CI on all three OSes. If safe behavior cannot be proved, disable and document the affected path under D15; ordinary missing implementation remains a blocker. No runtime or plugin is declared passing by architecture inspection alone. |
| RM-05 | Migrate Electron `safeStorage` credentials without plaintext fallback or silent deletion. Preserve legacy encrypted records until the user explicitly transfers a credential to OS storage or re-enters it; handle unavailable decryption as recoverable setup. | Electron credential adapter and migration requirement MIG-009. Encrypting with a different OS backend cannot be assumed to decrypt old bytes. CI uses synthetic credentials only. |
| RM-06 | Use GitHub Actions as the sole executable validation environment. Parallelize independent read-only checks and post-package audits; keep build/test/artifact prerequisites serialized, and avoid parallel Cargo commands sharing a target directory unless their workspace/output isolation is explicit. | CI preparation passed on all three OSes at `f38c0ef40cd073cc8c6aada74adbf190b15ac0f2`; `evidence/parallel-ci.json`. |
| RM-07 | Keep requirement status, mapping and evidence distinct: prior Electron results are historical, Rust rows begin pending, genuinely external human/signing/service/publication work remains external_pending, and only obsolete runtime decisions/proposals are superseded. | The reviewed 196-row inherited inventory plus Rust-specific rows in `requirements.json`. GitHub inventory CI checks this distinction. |
| RM-08 | Keep documentation maintenance in every migration phase and require a final cutover audit for correctness and stale Electron guidance. Preserve historical documents as historical and never advertise pending or unsupported behavior as shipped. | Added migration acceptance row MIG-016 from the updated goal. The audit is an implementation gate, not a substitute for product behavior or external handoff. |
| RM-09 | Use `egui_commonmark = 0.25.0` for bounded, read-only CommonMark rendering in the native egui transclusion preview. Disable image loading and network fetching; attachment bytes must be mediated through the vault boundary before they can be displayed. | This OpenObsidian-specific UI dependency is aligned with egui 0.36 and recorded in `crates/ui-egui/Cargo.toml`. Its default image loaders can read local files, so the migration keeps those features disabled while the renderer is used for note text. |
| RM-10 | Preview only allowlisted PNG, JPEG, GIF, WebP, BMP and ICO attachments through bounded vault reads and dimension/pixel-limited decoding. Convert validated pixels to native textures; do not enable egui file, HTTP or default image loaders. Keep SVG, AVIF and other attachments inert until their format-specific safety and compatibility are established. | OpenObsidian-specific `image = 0.25.10` (MIT OR Apache-2.0), default features disabled, selected for the six explicit decoder formats. Per-file byte, dimension and report-wide pixel/count limits are enforced in the vault resolver. CI must verify behavior on Ubuntu, macOS and Windows before this decision is considered implemented. |
| RM-11 | Evaluate `latex-rust = "=1.0.2"` as a development-only candidate for native Markdown math preview. Keep it out of the application runtime until exact-SHA CI verifies representative formula rendering and honest rejection of unsupported syntax across all three desktop platforms, and redistribution notices are prepared. | Candidate is MIT OR Apache-2.0 and embeds STIX Two Math under SIL OFL 1.1; the PNG feature uses `tiny-skia` and does not enable the crate's optional egui 0.28 integration. See the [1.0.2 manifest](https://raw.githubusercontent.com/thclark/LaTeX-Rust/main/Cargo.toml), [NOTICE](https://raw.githubusercontent.com/thclark/LaTeX-Rust/main/NOTICE), and [capability inventory](https://raw.githubusercontent.com/thclark/LaTeX-Rust/main/documents/CAPABILITIES.md). These are upstream claims; the probe is evaluation evidence, not a compatibility certification. |

## Open feasibility questions

R1 resolves the architecture of the isolated legacy-plugin execution surface using representative unchanged artifacts and cross-platform CI evidence. R1 also validates available Rust 1.95 runners, egui Linux system dependencies and native artifact output. These questions remain active acceptance work; they do not permit dropping plugin targets, changing the stable Obsidian baseline or treating a scaffold as a completed migration.
