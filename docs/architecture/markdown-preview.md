# Native Markdown preview

The Rust UI uses `egui_commonmark = 0.25.0` for native CommonMark rendering. That renderer provides tables, task lists, strikethrough, footnotes, and a small set of alert callouts. The OpenObsidian preview contract treats some of those extensions as source-only until their exact behavior is supported by the migration.

`crates/doc` pins `pulldown-cmark = 0.13.4` (MIT) as a direct dependency for a read-only dialect preflight. It is already present in the locked dependency graph through `egui_commonmark`; the direct pin lets document code identify unsupported constructs using parser events without depending on a UI crate. The pin also matches the locked version used by the UI renderer. See the upstream [egui_commonmark 0.25.0 manifest](https://github.com/lampsitter/egui_commonmark/blob/v0.25.0/egui_commonmark/Cargo.toml), [egui_commonmark renderer parser options](https://github.com/lampsitter/egui_commonmark/blob/v0.25.0/egui_commonmark_backend/src/pulldown.rs), and [pulldown-cmark 0.13.4 package metadata](https://docs.rs/crate/pulldown-cmark/0.13.4/source/Cargo.toml.orig).

Before the UI invokes the renderer, `analyze_markdown_preview` classifies footnotes, math, diagram and plugin fences, raw HTML, wiki links, and highlights. If any are present, the bounded transclusion source slice is displayed as monospace text and the UI names those constructs. It does not normalize or write the Markdown. Markdown and HTML in code blocks remain code; their contents do not trigger the source-only fallback. Other supported Markdown continues through `egui_commonmark`.

This is an initial safe-rendering slice. Wiki-link resolution, highlight rendering, math, diagram rendering, safe HTML projection, and source-preserving editing remain incomplete, so C02.1 remains pending. The fixture `fixtures/markdown-dialects.json` records the intended dialect list, the current Rust preview boundary, and its golden classification cases. GitHub Actions on the exact implementation SHA is the only validation gate; no local executable validation is used.
